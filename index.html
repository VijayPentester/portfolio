Bug bounty & methodology

Active on Bugcrowd, learning in public through structured practice.

  1. Recon first

    Before touching a single request, I map the attack surface — subdomains, live hosts, endpoints, parameters — the same pipeline ReconPipe automates.

  2. Live as a normal user

    I spend real time using a target the way an ordinary user would before hunting, to build an intuition for what "normal" looks like and where it might break.

  3. Test against the OWASP core

    IDOR, broken authentication, XSS, CSRF, and business logic flaws — worked systematically rather than firing a scanner and hoping.

  4. Write it up properly

    A finding isn't done until it's reproducible from a clean write-up: impact, steps, evidence.

ReconPipe

Final-year project · Python CLI recon pipeline · Recon Engine module owned end-to-end

ReconPipe is a four-person final-year project: a command-line tool that chains reconnaissance utilities into one repeatable pipeline instead of running each one by hand. I own the Recon Engine module — the part that actually runs the scans and hands off clean data to the rest of the tool.

The pipeline runs Subfinder for subdomain enumeration, feeds live hosts through Httpx, pulls historical and current endpoints with Waybackurls and ParamSpider, then scans the result with Nuclei — de-duplicating and reconciling output at every handoff so the next stage isn't working with noise.

Next up: a risk score computed automatically from Nuclei severity right after each scan, feeding into a consolidated report.
